## 📖 Введение

Данное руководство предназначено для системных администраторов, ответственных за развертывание, настройку и поддержку Telegram-бота "Академический помощник". Бот помогает студентам в создании академических работ с использованием искусственного интеллекта.

### Ключевые обязанности администратора:
- Установка и настройка системы
- Мониторинг производительности
- Обеспечение безопасности
- Создание резервных копий
- Устранение неполадок
- Планирование обновлений

## 💻 Системные требования

### Минимальные требования:
- **ОС:** Ubuntu 20.04+ / CentOS 8+ / Debian 11+
- **CPU:** 2 ядра
- **RAM:** 4 GB
- **Диск:** 20 GB SSD
- **Сеть:** Постоянное подключение к интернету

### Рекомендуемые требования:
- **ОС:** Ubuntu 22.04 LTS
- **CPU:** 4+ ядра
- **RAM:** 8+ GB
- **Диск:** 50+ GB NVMe SSD
- **Сеть:** Высокоскоростное подключение

### Необходимые компоненты:
```bash
- Python 3.10+
- PostgreSQL 13+
- Redis 6.0+
- systemd
- git
```

### 4. Настройка автоматического мониторинга

#### Создание скрипта мониторинга:
```bash
sudo nano /opt/scripts/monitor_bot.sh
```
```bash
#!/bin/bash

LOG_FILE="/var/log/bot_monitoring.log"
DATE=$(date '+%Y-%m-%d %H:%M:%S')

echo "[$DATE] Starting monitoring check" >> $LOG_FILE

# Проверка статуса бота
if ! systemctl is-active --quiet academic-assistant-bot.service; then
    echo "[$DATE] ERROR: Bot service is not running" >> $LOG_FILE
    systemctl start academic-assistant-bot.service
    echo "[$DATE] Bot service restarted" >> $LOG_FILE
fi

# Проверка использования памяти
MEMORY_USAGE=$(ps -o pid,ppid,cmd,%mem,%cpu --sort=-%mem -p $(pgrep -f "python main.py") | tail -1 | awk '{print $4}')
if (( $(echo "$MEMORY_USAGE > 80.0" | bc -l) )); then
    echo "[$DATE] WARNING: High memory usage: $MEMORY_USAGE%" >> $LOG_FILE
fi

# Проверка дискового пространства
DISK_USAGE=$(df / | tail -1 | awk '{print $5}' | sed 's/%//')
if [ $DISK_USAGE -gt 85 ]; then
    echo "[$DATE] WARNING: High disk usage: $DISK_USAGE%" >> $LOG_FILE
fi

# Проверка соединения с Redis
if ! redis-cli -h localhost -p 6379 -a RedisBot2025! ping > /dev/null 2>&1; then
    echo "[$DATE] ERROR: Redis connection failed" >> $LOG_FILE
fi

# Проверка соединения с PostgreSQL
if ! sudo -u postgres psql -c '\q' academic_bot > /dev/null 2>&1; then
    echo "[$DATE] ERROR: PostgreSQL connection failed" >> $LOG_FILE
fi

echo "[$DATE] Monitoring check completed" >> $LOG_FILE
```

#### Настройка cron:
```bash

```

## 💾 Резервное копирование

### 1. Резервное копирование базы данных

#### Создание скрипта:
```bash
sudo nano /opt/scripts/backup_database.sh
```
```bash
#!/bin/bash

BACKUP_DIR="/opt/backups/database"
DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="academic_bot"
DB_USER="bot_user"
RETENTION_DAYS=7

# Создание директории для резервных копий
mkdir -p $BACKUP_DIR

# Создание резервной копии
pg_dump -h localhost -U $DB_USER -d $DB_NAME | gzip > $BACKUP_DIR/academic_bot_$DATE.sql.gz

# Проверка успешности создания копии
if [ $? -eq 0 ]; then
    echo "$(date): Database backup created successfully: academic_bot_$DATE.sql.gz"
else
    echo "$(date): Database backup failed" >&2
    exit 1
fi

# Удаление старых копий
find $BACKUP_DIR -name "academic_bot_*.sql.gz" -mtime +$RETENTION_DAYS -delete

echo "$(date): Old backups cleaned up (older than $RETENTION_DAYS days)"
```

#### Восстановление из резервной копии:
```bash
# Список доступных копий
ls -la /opt/backups/database/

# Восстановление
gunzip -c /opt/backups/database/academic_bot_YYYYMMDD_HHMMSS.sql.gz | \
sudo -u postgres psql academic_bot
```

### 2. Резервное копирование Redis

#### Создание скрипта:
```bash
sudo nano /opt/scripts/backup_redis.sh
```
```bash
#!/bin/bash

BACKUP_DIR="/opt/backups/redis"
DATE=$(date +%Y%m%d_%H%M%S)
REDIS_DIR="/var/lib/redis"
RETENTION_DAYS=7

mkdir -p $BACKUP_DIR

# Создание резервной копии Redis
redis-cli -h localhost -p 6379 -a RedisBot2025! BGSAVE

# Ожидание завершения сохранения
while [ $(redis-cli -h localhost -p 6379 -a RedisBot2025! LASTSAVE) -eq $(redis-cli -h localhost -p 6379 -a RedisBot2025! LASTSAVE) ]; do
    sleep 1
done

# Копирование файла дампа
cp $REDIS_DIR/dump.rdb $BACKUP_DIR/redis_dump_$DATE.rdb
gzip $BACKUP_DIR/redis_dump_$DATE.rdb

echo "$(date): Redis backup created: redis_dump_$DATE.rdb.gz"

# Удаление старых копий
find $BACKUP_DIR -name "redis_dump_*.rdb.gz" -mtime +$RETENTION_DAYS -delete
```

### 3. Резервное копирование кода

```bash
sudo nano /opt/scripts/backup_code.sh
```
```bash
#!/bin/bash

BACKUP_DIR="/opt/backups/code"
DATE=$(date +%Y%m%d_%H%M%S)
SOURCE_DIR="/opt/academic_assistant_bot"

# Создание архива исходного кода

    --exclude='venv' \

    --exclude='.git' \
    --exclude='*.pyc' \
    -C $SOURCE_DIR .

echo "$(date): Code backup created: code_backup_$DATE.tar.gz"

# Удаление старых копий
find $BACKUP_DIR -name "code_backup_*.tar.gz" -mtime +30 -delete
```

### 2. Обновление приложения

#### Создание скрипта обновления:
```bash
sudo nano /opt/scripts/update_bot.sh
```
```bash
#!/bin/bash

APP_DIR="/opt/academic_assistant_bot"
BACKUP_DIR="/opt/backups/pre_update"
DATE=$(date +%Y%m%d_%H%M%S)

echo "Starting bot update process..."

# Создание резервной копии перед обновлением
mkdir -p $BACKUP_DIR
tar -czf $BACKUP_DIR/pre_update_backup_$DATE.tar.gz -C $APP_DIR .

# Остановка сервиса
systemctl stop academic-assistant-bot.service

# Обновление кода
cd $APP_DIR
sudo -u botuser git fetch origin
sudo -u botuser git pull origin main

# Активация виртуального окружения и обновление зависимостей
sudo -u botuser $APP_DIR/venv/bin/pip install --upgrade pip
sudo -u botuser $APP_DIR/venv/bin/pip install -r requirements.txt

# Применение миграций базы данных (если есть)
if [ -f alembic.ini ]; then
    sudo -u botuser $APP_DIR/venv/bin/alembic upgrade head
fi

# Запуск сервиса
systemctl start academic-assistant-bot.service

# Проверка статуса
sleep 10
if systemctl is-active --quiet academic-assistant-bot.service; then
    echo "Bot update completed successfully!"
else
    echo "Bot update failed! Check logs and restore from backup if needed."
    exit 1
fi
```

```bash
sudo nano /opt/scripts/security_check.sh
```

```bash
#!/bin/bash

LOG_FILE="/var/log/security_check.log"
DATE=$(date '+%Y-%m-%d %H:%M:%S')

echo "[$DATE] Starting security check" >> $LOG_FILE

# Проверка неудачных попыток входа
FAILED_LOGINS=$(grep "Failed password" /var/log/auth.log | grep $(date '+%b %d') | wc -l)
if [ $FAILED_LOGINS -gt 10 ]; then
    echo "[$DATE] WARNING: High number of failed login attempts: $FAILED_LOGINS" >> $LOG_FILE
fi

# Проверка процессов с высокими привилегиями
ROOT_PROCESSES=$(ps aux | grep -v '\[' | awk '$1=="root" {print $11}' | sort | uniq -c | sort -nr)
echo "[$DATE] Root processes summary:" >> $LOG_FILE
echo "$ROOT_PROCESSES" >> $LOG_FILE

# Проверка сетевых соединений
SUSPICIOUS_CONNECTIONS=$(netstat -tulpn | grep LISTEN | grep -v -E "(127.0.0.1|::1)")
if [ ! -z "$SUSPICIOUS_CONNECTIONS" ]; then
    echo "[$DATE] WARNING: Non-local listening services:" >> $LOG_FILE
    echo "$SUSPICIOUS_CONNECTIONS" >> $LOG_FILE
fi

echo "[$DATE] Security check completed" >> $LOG_FILE
```

```sql
ALTER SYSTEM SET log_min_duration_statement = 1000;
SELECT pg_reload_conf();

-- Просмотр активных запросов
SELECT pid, now() - pg_stat_activity.query_start AS duration, query 
FROM pg_stat_activity 
WHERE (now() - pg_stat_activity.query_start) > interval '5 minutes';
```

```bash
#!/bin/bash
# /opt/scripts/daily_check.sh
```
